# Ten-level scope matrix

A level is a label for an explicitly approved scope in one named domain. It is not a universal trust rating or capability switch. Treat the descriptions below as possible additions to a grant, not automatic authority. The approving policy must name the actual actions and limits. A grant in one domain does not transfer to another, and an owner may reserve or exclude any action at any level.

| Level | Possible added scope when explicitly granted |
| --- | --- |
| L1 | Complete a specifically assigned, bounded task and report its result. |
| L2 | Choose reversible task details within the written assignment. |
| L3 | Select among preapproved methods and sequence work inside the grant. |
| L4 | Notice a likely gap, risk, or missing step and propose the next action; do not exceed the current grant while preparing the proposal. |
| L5 | Start named, routine actions in one domain within written limits. |
| L6 | Resolve routine exceptions that the policy explicitly describes; escalate unlisted cases. |
| L7 | Complete a preauthorized multi-step workflow inside one named domain. |
| L8 | Coordinate actions across multiple named domains, but only where each domain grants the required actions. |
| L9 | Handle bounded edge cases covered by a written exception path; stop at any reserved or restricted decision. |
| L10 | Use the maximum routine scope explicitly delegated across named domains and actions. Owner-reserved decisions, restrictions, limits, and host permissions remain in force. |

## Apply the matrix

- Set a level independently for each domain, with a written action list and exclusions.
- Classify decisions as reversible or hard to reverse. If the classification is uncertain, treat the decision as requiring escalation.
- Use documented preference evidence only. If no relevant preference is recorded, mark it unknown rather than inferring one.
- Track whether proposed work was held or actually shipped. Do not describe an unverified proposal as a real outcome.
- Use evidence to recommend a review, not to change scope automatically. A clean window grants no authority to publish, spend, use accounts, or perform other actions outside the explicit grant.

The reversible versus hard-to-reverse “door” analogy is commonly associated with Amazon's decision-making vocabulary. This matrix uses it as a general aid and does not represent an Amazon policy.
